Twitter-/X-ID dekodieren
Analyseergebnis

Alle Objekte von X / Twitter (Tweets, Nutzer, DMs) verwenden Snowflake-IDs: Die oberen 41 Bit sind ein Millisekunden-Zeitstempel, die unteren 22 Bit Maschine und Sequenz. IDs bis 29700859247 sind reine fortlaufende Nummern vor Snowflake, ohne eingebettete Zeit.

Erzeugt

Twitter- und X-ID-Decoder

Every X (formerly Twitter) object ID is a Snowflake. Paste one to recover its creation time, machine and sequence fields.

IDs at or below 29700859247 are pre-Snowflake sequential numbers with no embedded time; the tool says so clearly.

Features

  • Creation time — Recovers the UTC and local creation time of the ID, to the millisecond.
  • Boundary detection — Recognizes pre-Snowflake sequential IDs and clearly reports "no embedded time".
  • Time to ID — Given a time, build that moment's Twitter Snowflake ID for time-range lookups.

How to use

  1. Paste any tweet, user or DM numeric ID.
  2. The right side shows creation time, machine and sequence; very early IDs report no time.
  3. Enter a time on the right and click "Time to ID" to build one.

FAQ

Why do some IDs have no time?

IDs before Snowflake launched in Nov 2010 are plain sequential numbers (about <= 29700859247) and contain no time to recover.

Does decoding need an X login?

No. The Snowflake timestamp is encoded in the ID itself; this tool computes locally with no X API involved.
